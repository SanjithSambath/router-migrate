Definitions
sites_found
production LLM sites: API calls (chat, responses, messages, embeddings, images...) and framework model constructions; tests/examples/evals excluded
migrated
sites whose traffic goes to Router when RAMP_ROUTER_API_KEY is set (client patched in the same file or the only patchable client family in the repo, surface served by Router, model in catalog or chosen at runtime with at least one of the repo's model names for that family in the catalog)
handoff
sites that need an agent-made code change (other-vendor SDK whose model Router serves, raw HTTP, other gateways)
kept
sites that stay on their provider by design (no Router endpoint, e.g. embeddings; another vendor's endpoint or vendor-named module; stateful Responses chains; provider-side vector stores/files)
flagged
sites Router could serve but the tool does not move automatically (unmapped model, runtime-chosen model with no catalog match among the repo's model names, Anthropic beta header, per-tenant provider keys)
callsite_coverage
migrated / sites_found
weighted_coverage
migrated / Router-eligible sites (generation surfaces Router can serve)
tests_before/after
the repo's own offline test suite (or typecheck where it has none), Router off, before vs after migrating
tests, Router on
the same tests with RAMP_ROUTER_API_KEY set and Router pointed at router-sim. Suites that mock HTTP by exact URL (VCR cassettes, httpx mocks for api.openai.com/api.anthropic.com) cannot match once requests go to Router; those failures are mock misses, not behavior changes (see per-repo notes). Shown as 'N/A: suite mocks the SDK/HTTP' when the run sent 0 requests to router-sim (sim_requests_from_tests = 0): the suite never exercised Router
sim_requests_from_tests
requests that reached router-sim during the Router-on test run (0 means the suite mocks the SDK or HTTP; it then validates nothing)
sim_valid_pct
replay_ok / replay_unique_requests: each migrated site's request is rebuilt from its statically known literal kwargs (tools, response_format, thinking, output_config, extra_headers, temperature, max_tokens, stop, reasoning_effort...; non-literal values are not known and not sent), its literal model when Router's catalog resolves it (else a default model), and synthetic message content, then sent through the vendored runtime to router-sim; sites with an identical request shape count once. It does not run the repo's own code path. Rows marked 'legacy def.' come from older result files (one synthetic 'pong' request per site, reused verdicts counted per site) and are excluded from the mean
replay_unique_requests / replay_ok
unique request shapes replayed / accepted by router-sim
live_success_pct
same replay against api.router.com (null when not run)
