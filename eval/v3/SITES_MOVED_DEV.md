## Method notes

- Request shape: the scanner's literal kwargs (verify.replay_kwargs; LangChain/LlamaIndex constructor settings mapped to wire names), the literal model when static (a non-catalog literal stays non-catalog, so it stays on the provider unless the policy maps it), else gpt-4o-mini / claude-haiku-4-5. Non-literal kwargs are invisible to this check.
- Runtime: router_migrate/runtime/router_runtime.py as it is now (rendered with the current catalog), with the trial tree's compiled policy installed via set_policy and the site's feature id (`<file>:<function>`) as the call-stack feature, so drop_params / model_map trade-offs apply exactly as in production. TS sites are checked with the Python planner (the two runtimes share the policy parity fixtures); client-level wrap options (unlock_hosts, drop_betas, operator_key_only) are not read, but measure-only scoring already excludes those clients unless a probe confirms them.
- Request host: where the call's requests really go. The scanner cannot resolve a config-driven base URL (`base_url=config.GROQ_BASE_URL`) or which of several clients reaches a call (AI-Scientist's create_client), and measure-only scoring counts a wrapped config-driven client as routed. The route check therefore sends the request to the host the matched inventory site's `endpoint` names (a runtime fact, not an outcome judgment); a client re-pointed at Router by the arm is sent to Router as written. Without an inventory (dev set) a static base URL is used, else the provider default (optimistic).
- Router validity: the request the runtime would send is checked by router-sim (fallback off). A Router rejection falls back to the provider in production, so it does not count as Router traffic.
- Broken, $ and minutes are the saved result.json values (tests/typecheck and the independent check at trial time).
