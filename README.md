# router-migrate

Move a codebase's production LLM calls onto [Ramp's Router](https://router.com) in one command, without breaking anything.

```bash
router-migrate run .          # scan -> plan -> apply -> verify -> report
export RAMP_ROUTER_API_KEY=... # traffic Router can serve now goes to Router; everything else keeps working as before
```

router-migrate finds every OpenAI / Anthropic / LangChain / Vercel AI SDK / LlamaIndex / LiteLLM call in a Python or TS/JS
repo. It patches only the lines where clients are constructed, and vendors one small, readable runtime file that speaks Router's
API. Existing code keeps calling `chat.completions.create` and reading `.choices[0].message`. The runtime translates those calls
to Router's Responses API, and translates the replies and streams back.

- **Inert until you opt in.** With no `RAMP_ROUTER_API_KEY`, every patched line returns the original client, so tests, mocks and
  cassettes see exactly the same requests. `ROUTER_MIGRATE_DISABLE=1` is the kill switch.
- **Never a hard failure.** Requests Router can't serve exactly go to the original provider unchanged: embeddings, images, audio,
  `n>1`, logprobs, `seed`, models outside the catalog, provider-side vector stores, and other vendors' base URLs. If Router still
  refuses a request before generating anything (unknown parameter, model not available to the key, 501), the original request is
  sent to the provider once.
- **Every site accounted for.** REPORT.md lists each call site as migrated / kept / flagged / handoff, with the exact reason.
  HANDOFF.md gives a coding agent the judgment calls with "done when" criteria.
- **Verified.** `verify` runs your tests before and after. It then runs them with Router on against **router-sim**, a local
  Router stand-in that enforces Router's measured behavior. It also replays every migrated site through the vendored runtime,
  and optionally against the live API with a dollar cap.

## Results (15 pinned open-source repos)

Generated by `make eval`; details are in [eval/SCOREBOARD.md](eval/SCOREBOARD.md) and the one-page [WRITEUP.md](WRITEUP.md).
- **Coverage:** 48 of 170 production LLM sites migrated. That is 45% of Router-eligible sites, and 75% of eligible sites that call
  OpenAI/Anthropic directly.
- **Breakage:** tests and typecheck are unchanged in all 15 repos.
- **Replay:** every migrated site's request shape replayed through the vendored runtime against router-sim and live Router: 100% valid.
- **Against the docs' migration prompt** (run by a Claude agent): it moved more sites, but it left failing tests or new type errors in
  8 of 15 repos; in the repos it left intact it moved 32 sites, against router-migrate's 48.

## v3: agent-native migration (`router-migrate run --agent claude`)

```bash
router-migrate run . --test-cmd "<tests>" --agent claude   # floor, then a coding agent on the residue, then the gate
router-migrate run .                  # floor + ledger + worklist only (no agent); idempotent
router-migrate check FILE:LINE        # does the runtime reroute this call as the code stands? routes | wont_route | routes_if
router-migrate wrap FILE:LINE         # the deterministic wrap at any client construction (factories too)
router-migrate claim FILE:LINE --outcome kept --reason R_OTHER_HOST --why "..." --evidence config.py:12
router-migrate finish .               # the gate; reverts agent edits to the floor after 3 failures; --hook for a Stop hook
router-migrate improve . [--agent claude]   # Improve: cards for every Router lever from your judgments; --agent runs the judging session
router-migrate judge FILE:LINE latency background --why "..." --evidence app/tasks.py:30   # latency | task | model | cacheable
```
After the gate, `run --agent claude` continues into Improve and opens the dashboard (the whole run, a lever grid, cards
with tool facts vs agent rationale, a repo-specific Router setup checklist). Approve cards there and click "Apply N
changes"; then run `finish` again. Results: [eval/v3/IMPROVE_RESULTS.md](eval/v3/IMPROVE_RESULTS.md); the whole loop end to
end (run, approve and Apply in the browser, `finish`, the request each feature now sends): [eval/v3/e2e/](eval/v3/e2e/).
On 10 fresh repos the agent + toolkit arm made 10 correct moves, 0 wrong, broke 0 repos ([eval/v3/RESULTS.md](eval/v3/RESULTS.md)).
Design: [SPEC_V3.md](SPEC_V3.md). Prompt: [router_migrate/prompts/migrate.md](router_migrate/prompts/migrate.md).

## v2: migrate, then unlock, then improve (`router-migrate up`)

```bash
router-migrate up .            # v1 pass + Improve cards, then a local dashboard (127.0.0.1, session token)
router-migrate up . --agent    # same, no dashboard: prints undecided cards as JSON, exit 2 until every card is decided
router-migrate decide <id> approve|dismiss --reason R|postpone --until 2026-12-01|shadow-first
router-migrate apply . --decisions   # router.policy.json -> compiled router_policy.py / routerPolicy.ts; approved unlock edits
router-migrate status .        # effective policy per feature; exit 1 if the compiled policy is stale or an entry is orphaned
```

v1 stays the automatic, lossless first pass, unchanged. v2 adds cards, and nothing applies itself.

| Lever | What it does | How it applies |
|---|---|---|
| `unlock.vendor_endpoint` | another vendor's endpoint whose model is an exact Router catalog id is served by Router | code edit: `unlock_hosts=[...]` on the client wrap; checked per request |
| `unlock.stated_loss` | an Anthropic request blocked only by droppable beta flags moves once you accept the stated loss | code edit: `drop_betas=[...]` |
| `attr.metadata` | spend tags (`metadata.product`) on every Router-served feature | compiled policy |
| `cache.key` | `prompt_cache_key` for OpenAI-model features with a long static prompt | compiled policy |
| `tier.flex_background` | `allow_flex_tier: true` for background jobs on models with a flex tier: −50% per call (measured on gpt-5.4-mini) | compiled policy |
| `fallback.candidates` | `models: [original, ...]`, capability-matched, used on pre-stream failures only | compiled policy |
| `model.deprecated` / `model.newer_cheaper_same_family` / `model.right_size` | model-change recommendations, only where the app or its operator owns the model | **never applied** (cards only) |

Every lever the rules rejected is listed under "Considered, not recommended", with the reason. The lossless number and the
with-unlocks number are always reported side by side, never summed. Measurements behind the rules are in
[research/m0_measurements.md](research/m0_measurements.md); the results are in [eval/SCOREBOARD_V2.md](eval/SCOREBOARD_V2.md).

## Install

Requires Python 3.9+ and Node 18+ (Node is only needed for TS/JS repos).

```bash
git clone <this repo> router-migrate && cd router-migrate
make setup                                # .venv (libcst, httpx, SDKs for verify) + node_modules (ts-morph), all local
export PATH="$PWD/bin:$PATH"              # bin/router-migrate
router-migrate --help
```

## Quickstart

```bash
cd your-repo
router-migrate scan .                     # what's there
router-migrate plan . --dry-run           # the exact diff, nothing written
router-migrate apply .                    # patch + vendor the runtime; writes .router-migrate/{REPORT,HANDOFF}.md
router-migrate verify . --test-cmd "pytest -q"     # tests before/after + router-sim checks
RAMP_ROUTER_API_KEY=... router-migrate verify . --live --budget 0.10   # optional: real Router, capped spend
router-migrate report .
```

Typical diff (openai/swarm):

```diff
+try:  # router-migrate: route LLM traffic through Ramp's Router when RAMP_ROUTER_API_KEY is set
+    from .router_runtime import wrap_openai as _router_wrap_openai
+except ImportError:  # router-migrate: module executed as a script
+    try:
+        from router_runtime import wrap_openai as _router_wrap_openai
+    except ImportError:  # router-migrate: runtime not importable from here; this module keeps its original behavior
+        _router_wrap_openai = lambda c, *a, **k: c  # noqa: E731
 ...
-            client = OpenAI()
+            client = _router_wrap_openai(OpenAI())
```

TS/JS:

```diff
-const client = new OpenAI({ apiKey });
+const client = new OpenAI({ apiKey, ...routerOptions() });
```

## How it works

```
your code ── client.chat.completions.create(...) ──► OpenAI SDK ──► router transport (vendored)
                                                                    ├─ servable? ─► Router POST /v1/responses ─► translated back to a ChatCompletion / chunk stream
                                                                    └─ otherwise ─► original provider, request untouched
```

| Surface | What happens |
|---|---|
| OpenAI `chat.completions` (sync, async, stream, tools, `parse`, legacy `functions`) | translated to `/v1/responses` and back, including SSE |
| OpenAI `responses` | sent to Router minus `store` (Router rejects `store:true`); `previous_response_id` chains that started on Router continue with the history inline |
| Anthropic `messages` (create, stream, `count_tokens`) | sent to Router `/v1/messages`; model id mapped |
| LangChain `ChatOpenAI` / `ChatAnthropic` | `_router_wrap_langchain(ChatX(...))`: the SDK clients LangChain built are wrapped in place |
| LlamaIndex, LiteLLM | `http_client` injection, or install hook |
| Vercel AI SDK `createOpenAI` / `createAnthropic` / default `openai` provider | `fetch: routerFetch()` |
| embeddings, images, audio, files, assistants, vector stores, legacy completions | **kept** on the provider (Router has no such endpoint; measured 404) |
| Azure, Bedrock, Vertex, Groq/OpenRouter/DeepSeek/Ollama base URLs | **kept** |
| google-genai / Mistral / Cohere calls whose model Router serves; raw HTTP to api.openai.com | **handoff** to a coding agent |
| Anthropic beta, stateful Responses use (`retrieve`, `conversation`, `store=True`), models outside the catalog, per-tenant keys | **flagged** or **kept**; the runtime keeps them on the provider |

### Rules the runtime applies (each one measured against the live API)

| Rule | Why |
|---|---|
| `max_tokens` -> `max_output_tokens`; values below 16 stay on the provider | Responses rejects `max_tokens`; its minimum is 16 |
| `stop` stripped for OpenAI models and emulated client-side (works across stream chunks) | Router returns 501 for `stop` on OpenAI models |
| `temperature` / `top_p` dropped where the catalog says unsupported | 400 otherwise |
| tools sent as flat Responses tools with explicit `strict: false` | Responses defaults to strict schemas |
| `store` removed; Router-started chains replayed inline; `include: reasoning.encrypted_content` for OpenAI reasoning models | Router keeps no server state |
| `prompt_cache_key` added for Claude | Claude via Responses doesn't cache without it |
| `service_tier: "default"` unless the caller set one | flex is the account default and adds latency |
| dated model ids mapped only where Router itself reports the equivalence | dated ids 404; undated aliases can be newer snapshots |
| `metadata.feature = "<file>:<function>"` | per-feature cost attribution with no call-site edits |

## Limits

- Python and TS/JS only. Python clients built through deep factories, and TS clients passed in from outside the repo, show up as
  **handoff** rather than being guessed.
- Models outside the Router catalog stay on their provider. That is deliberate: substituting a different model is a product decision
  (`ROUTER_MIGRATE_MODEL_MAP` opts in per model).
- The runtime installs itself under the client's own transport and proxy mounts, so certificates, `proxy=`, `HTTP(S)_PROXY`,
  headers, hooks and pools all still apply.
- `previous_response_id` chains that start on Router are kept in process memory (last 256). On a multi-process server, a turn that
  lands on another worker gets a clear error. The planner keeps clients that use stateful Responses features off Router for this
  reason.
- `metadata.feature` / `prompt_cache_key` send a repo-relative `file:function` name to Router; `ROUTER_MIGRATE_FEATURE_TAG=off`
  disables them.
- Some Router features are only reachable from code already on the Responses API (built-in tools, reasoning items, `models`
  fallback lists). Code that is moved by translation gets plain generation.
